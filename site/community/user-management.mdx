title: "User management"
description: "How the THG Community bot registers members in PostgreSQL on every command."
---

The bot automatically ensures that everyone who runs a command has a row in the database. No separate
sign-up step — registration happens transparently before the command handler runs.

## How it works

1. **Event handler** — user management runs from `src/events/interactionCreate.ts` before slash commands,
   component presses, and modal submits. Bots are skipped (`!interaction.user.bot`).
2. **Automatic check** — the handler calls `ensureUserExists(discordId, username)` for the caller.
3. **Automatic creation** — if no row has that `discordId`, one is created.
4. **Username updates** — if the row exists but the Discord username changed, it is updated.

Sending a normal channel message does **not** register anyone — the old `messageCreate` path served prefix
commands the bot no longer has. `/link` also calls `ensureUserExists` itself so a link can always relate to a
row.

`/skyblock` and `/networth` are **deferred** (`deferReply`) before `ensureUserExists`, because the first
Prisma query after a restart can take long enough to expire Discord's three-second acknowledgement window.

## Database model

```prisma
model User {
  id        String   @id @default(uuid())
  discordId String   @unique
  username  String
  language  String   @default("nl")
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  // relations: MinecraftLink, FeatureRequest, …
}
```

The internal `User.id` UUID is what foreign keys use — not the Discord snowflake. `language` remains in the
schema with a default of `nl` but is **never read**; the bot is English-only.

## Key functions

### `ensureUserExists(discordId, username)`

- Looks up by Discord id.
- Creates a row when missing.
- Updates `username` when it changed.
- Returns the database user object.

### `getUserByDiscordId(discordId)`

Retrieves a user by Discord id without creating one.

## Event integration

Slash interactions call `ensureUserExists` before dispatch:

```typescript
if (interaction.user) {
  await ensureUserExists(interaction.user.id, interaction.user.username);
}
```

For `/skyblock` and `/networth`, the defer happens in `interactionCreate` **before** this call.

## Error handling

Database errors are logged and rethrown. In `interactionCreate` they land in the same try/catch as the
command, so the error handler reports them and the member gets an ephemeral error reply instead of a command
that silently does nothing. Production (`main.ts`) closes the Prisma connection on SIGINT/SIGTERM;
development (`dev.ts`) does not.

## Using it in commands

Any command can assume the caller has a `User` row after the event hook runs:

```typescript
const user = await ensureUserExists(
  interaction.user.id,
  interaction.user.username,
);

await prisma.featureRequest.create({
  data: {
    userId: user.id,
    // …
  },
});
```

`/profile` uses the same helper instead of duplicating create/update logic.
